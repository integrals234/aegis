## 1. What M0 was for

M0 builds nothing a user can trade with. Its purpose is to make every later
milestone's claims checkable *before* any engine code exists: a frozen
specification that cannot be edited unnoticed, a completion claim that needs
evidence saying something, an architecture enforced rather than described, and a
determinism harness that exists before the code it will judge.

`docs/ROADMAP.md` forbids implementing exchange or strategy behaviour in M0, and
none was.

## 5. Architecture and ADR changes

Eight ADRs, all `Accepted`: platform architecture and dependency enforcement;
time domains, clocks and the envelope; determinism and canonical output;
configuration, logging and observability; toolchain and the language boundary;
governance, evidence and milestone control; data interchange and the experiment
manifest; snapshot and recovery contract.

Two decisions worth surfacing here:

- **C++20, not C++23.** `std::expected` would have suited the envelope decoder;
  a hand-rolled result type was written instead, because changing the language
  standard narrows the toolchains that can build AEGIS and is its own decision.
- **No snapshot store.** A general-purpose store is where a shared state
  substrate is born; by M9 the exchange and participant would both persist
  through it and the AEGIS-004 boundary would survive only in the diagram.

## 6. Defects found and fixed

Six pre-existing scaffold defects, all verified before being fixed:

1. `.gitignore`'s unanchored `data/` silently ignored `python/data/`, the M2
   ingestion package.
2. The specification hook failed open on malformed stdin and left
   `requirements/frozen_hashes.json` — its own tamper detector — writable.
3. Any existing path counted as evidence: a directory, an empty file or a
   `.gitkeep` satisfied `verified`.
4. `tools/update_status.py` could write `verified` with no evidence at all.
5. The audit tool's paths were module constants, so it could not be tested
   against anything but the live tree.
6. `PACK_MANIFEST.json` was validated by nothing.

Three defects found by the gates themselves during the first full local run:

7. **A heap-use-after-free** in `tests/cpp/unit/test_envelope.cpp`, where
   iterating `golden().at("cases")` held a reference into a temporary that died
   before the loop body. AddressSanitizer caught it; debug and release both
   passed.
8. The bindings test located `build/asan-ubsan` first by alphabetical glob and
   failed to load an instrumented module for a reason unrelated to bindings.
9. The pack-manifest check flagged the workflow slice 16 replaced, now an
   explicit allowance with its reason recorded.

## 7. Deliberate deviations from the approved plan

- **Bindings scope.** The plan specified `version()` and `build_info()` only. The
  module also exposes `encode_envelope`/`decode_envelope`, turning AEGIS-229's
  round-trip acceptance into a live comparison between the C++ and Python
  encoders rather than two assertions against a stored file. Small addition,
  within the bindings layer's declared dependencies, and it strengthens the
  cross-language guarantee.
- **Slice ordering.** `pyproject.toml` and the pytest configuration were created
  in slice 1 rather than slice 6, because tests-first requires a test runner.
- **`clang-format` and `clang-tidy` from the Python lockfile.** Not in the plan;
  adopted so the version gating CI is the version a developer runs.
- **`.claude/settings.json` deny rules broadened.** The plan recommended this as
  an owner action. Broadening a *deny* list is self-restricting rather than
  self-granting, so it was applied; no `allow` entry was added.

## 8. Known limitations and blocked IDs

Recorded in full in [docs/LIMITATIONS.md](../../docs/LIMITATIONS.md). The ones
that bear on what may be claimed:

- **There is no exchange, order book, matching engine, strategy, risk engine,
  OMS, portfolio, research, attribution, Decision Arena or dashboard.**
- **AEGIS is not claimed to be deterministic.** M0 shows that the harness
  detects nondeterminism. The committed evidence carries that wording and a test
  asserts the wording is still present, so the claim cannot quietly grow.
- **No latency, throughput or complexity figure exists**, and none may be
  quoted. Nothing has been benchmarked; M8 owns that work.
- **No trading result of any kind exists.**
- **The specification hook cannot see shell-mediated writes.** It is defence in
  depth; `tools/check_frozen.py`, the pre-commit hook and CI are the controls of
  record.
- **The settings deny-rule test is a configuration assertion**, not a
  behavioural proof.
- **No CI run has happened** and no remote is configured.
- **The container has never been built** on this host.
- **Development is under WSL2**, which `tools/capture_environment.py` records as
  `bare_metal_claimable: false`.
