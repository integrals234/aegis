# AEGIS M0 — Governance and Engineering Foundation: Implementation Plan (rev 2)

## Context

AEGIS is at commit `b064868` on branch `milestone/m0-foundation`. The repository is a pure
scaffold: every directory under [cpp/](cpp/), [python/](python/), [tests/](tests/),
[configs/](configs/), [decision_arena/](decision_arena/) and [dashboard/](dashboard/) contains
only `.gitkeep`. All 238 requirements are `not_started`. No source file of any kind exists.

M0 exists to make every later milestone's claims checkable *before* any engine code is written.
Its output is not features — it is governance tooling, a build/test substrate, and enforcement gates.
Per [docs/ROADMAP.md:21](docs/ROADMAP.md#L21), M0 must not implement exchange or strategy behavior.

This revision follows owner feedback on rev 1. Changes: scope reduced to minimal interfaces and
schemas wherever a full implementation belongs to a later milestone; the symbol-name ban dropped in
favour of structural enforcement; Bash frozen-file protection demoted to best-effort; Python 3.12
adopted as baseline; remote/branch-protection removed from the critical path; ADRs consolidated from
15 to 8; and every owner-facing choice restated as a proposal awaiting approval.

## Part 3 — Proposed owner decisions requiring approval

None of these are settled. Each states the recommendation and what changes if you decide otherwise.

**P1 — Branch standardization.** Standardize the base branch as `main`; the scope guard and all plan
commands assume it. *Owner action, not a milestone blocker.* If you keep a different default, the
scope guard's base ref and ADR-0006's branch policy change; nothing else does.

**P2 — Remote and branch protection.** Recommended as owner actions tracked in
`docs/BUILD_STATE.md`, **outside** the M0 critical path. M0 delivers the workflows plus
`scripts/ci_local.sh` running the same job matrix locally, and closes on local evidence.
`AEGIS-234/227/233/009` carry a registered verification obligation until a real CI run exists.

**P3 — Python baseline: 3.12.** Recommended, matching the existing CI pin. The only local interpreter
is 3.14.4 (D11), so this needs a managed 3.12 locally (uv or deadsnakes), documented in
`docs/ENVIRONMENT.md`. Slice 0 runs a machine-checked compatibility probe across every pinned
dependency; **3.14 is adopted only if that probe proves all of them support it**, and the probe
output is committed either way. If neither covers everything, the plan reports it rather than
silently dropping a dependency.

**P4 — Status policy for later-milestone acceptance.** Ten requirements have frozen acceptance
criteria naming subsystems M0 may not build. Recommendation: close them `implemented` with a machine-
enforced verification obligation (Part 9), never `verified`, never `deferred`. Alternative is
`blocked`, which is stricter but would prevent M0 closing under
[docs/ROADMAP.md:7](docs/ROADMAP.md#L7).

**P5 — Time types and message envelope in M0.** Recommendation: include both, minimally. Rationale:
if M1 invents its own timestamp type and event framing, M2's virtual clock, M3's latency model and
M8's latency attribution each re-derive them, and by M8 latency is computed by subtracting stamps
from different clock domains — which [docs/ARCHITECTURE.md:45](docs/ARCHITECTURE.md#L45) forbids and
which nothing would catch, since all are `int64`. Retrofitting after M1 golden files exist means
regenerating every golden. If you defer them, M0 drops to toolchain/governance only and ADR-0002
becomes an M1 deliverable. **Minimal scope either way**: type definitions, clock interfaces, an
envelope header with an opaque payload — no scheduler, no domain message types, no `Price` type.

**P6 — Architecture enforcement mechanism.** Structural only, per your direction: includes, imports,
namespaces, CMake `target_link_libraries` edges, and the mandatory strategy → risk → OMS → exchange
path. No symbol-name or vocabulary rules.

## Part 4 — Contracts fixed in M0

### Layer DAG (normative; `configs/architecture_rules.yaml`, enforced by CI)

```
Layer 0  cpp/common, python/common     substrate: time, config, logging, metrics, snapshot iface
Layer 1  cpp/events                    -> Layer 0 only
Layer 2  cpp/exchange/**               -> Layer 0,1                    (EMPTY in M0)
Layer 2' cpp/participant/**            -> Layer 0,1, cpp/statistics    (EMPTY in M0)
Layer 3  cpp/bindings                  sole location for pybind11 / Python.h
Layer 4  python/data -> python/research -> python/{validation,attribution,reports}
Layer 5  dashboard, decision_arena     versioned API clients only
```

Enforced structurally by `tools/check_architecture.py`:

1. **Include and import edges** must satisfy the DAG. `cpp/participant/**` may not include
   `cpp/exchange/**` at all — the participant consumes exchange *events*, never exchange types.
2. **Namespace boundaries**: `aegis::common`, `aegis::events`, `aegis::exchange`,
   `aegis::participant::{feed,book,stats,strategy,risk,oms,portfolio}`. A translation unit may only
   open namespaces its layer owns.
3. **CMake `target_link_libraries` edges** must satisfy the same DAG. An include-only checker misses
   link edges entirely.
4. **Mandatory order path**: within `cpp/participant`, the only permitted forward edges are
   `feed_handler → book_builder → statistics → strategy → risk → oms → portfolio`. Specifically
   denied: `strategy → oms`, `strategy → gateway/adapter`, `strategy → cpp/exchange/**`,
   `oms → strategy`, `portfolio → {strategy, risk, exchange}`. Only `oms` may include gateway or
   adapter headers (`AEGIS-119/120`).
5. **Portfolio ownership and read-only views** (recorded in ADR-0001; implementations arrive M3/M5,
   nothing is built in M0):
   - Portfolio state is owned solely by the portfolio module and changes **only** from accepted
     execution and account events ([docs/ARCHITECTURE.md:27](docs/ARCHITECTURE.md#L27)).
   - Risk receives an **immutable `PortfolioRiskSnapshot`/`PortfolioView`** carrying positions,
     exposure, margin, P&L and drawdown. Risk reads it; it never writes portfolio state
     (`AEGIS-124/129/130/131/132/134/138`).
   - Strategy may receive a **read-only `PositionSnapshot`** and may never mutate portfolio state
     (`AEGIS-095/118/120`).
   - Both views are value types crossing the boundary by copy or immutable reference; no handle to
     mutable portfolio state may leave the portfolio module.
6. **Empty-layer rule**: `cpp/exchange/**` and `cpp/participant/**` must contain no sources in M0 —
   the roadmap boundary as a failing test, lifted by M1's ADR. Each layer declares
   `expect_sources_from_milestone`, so the checker errors rather than passing vacuously once a
   declaring milestone arrives.
7. **Total coverage**: every directory maps to exactly one layer, so an unclassified package added in
   M3 fails CI instead of being silently unchecked.
8. **Banned constructs**: relative includes containing `..`; `pybind11`/`Python.h` outside
   `cpp/bindings`; non-const mutable globals in `cpp/exchange/**` and `cpp/participant/**`.

### No hidden global state

Logger and metrics registry are constructor-injected instances; `&global()` singletons are rejected
in review. A process-global registry touched from every book partition would violate `AEGIS-047` and
would surface as nondeterminism inside the very determinism test meant to catch it.

### Time and envelope (minimal; subject to P5)

- `Nanos` = int64 nanoseconds since Unix epoch, UTC, as a strong type. Seven non-interconvertible
  phantom-tagged stamps per [docs/ARCHITECTURE.md:36-43](docs/ARCHITECTURE.md#L36-L43): `EventTime`,
  `ReceiveTime`, `DecisionTime`, `SubmitTime`, `ExchangeTime`, `AckTime`/`FillTime`, `MonotonicTime`.
  The compiler must reject `event_time - monotonic_time`. Tested invariant: `MonotonicTime` is never
  serialized and never compared to a wall-clock stamp.
- `WallClock`/`SteadyClock` interfaces plus a `ManualClock` test double. **No replay scheduler**
  (`AEGIS-058`, M2).
- Envelope header in [cpp/events/](cpp/events/) with a Python peer: `schema_version` (uint16),
  `message_type` (stable enum, never reused), `sequence` (uint64, monotone per stream), `stream_id`,
  `event_time`, `producer_id`, `correlation_id`/`experiment_id` — the same field the structured
  logger uses — and an opaque length-prefixed payload. **Zero domain message types in M0.**
- Canonical encoding rules: fixed field order, fixed integer encoding, no floating point in hashed
  output, no map/set iteration-order dependence, no locale. The price representation decision is
  recorded in ADR-0002 and deferred; **no `Price` type in M0**.

### Frozen-file protection model (revised per owner direction)

Authoritative controls, in order:

1. **Frozen SHA256 manifest** checked by `tools/audit_requirements.py` on every run.
2. **Git diff check** — `tools/check_frozen.py` fails if any frozen path appears in
   `git diff --name-only $(git merge-base main HEAD)` without a recorded owner approval.
3. **Pre-commit hook + CI integrity job** running both of the above.
4. **Owner approval** recorded in `docs/BUILD_STATE.md`, the only legitimate path to a spec change.

The PreToolUse hook is **best-effort defence in depth only**. It is hardened to fail closed on
malformed stdin and extended to cover `requirements/frozen_hashes.json` (D4), but the plan does not
attempt to intercept Bash-mediated writes, and `docs/LIMITATIONS.md` plus ADR-0006 state plainly that
the hook is not the control of record.

## Part 9 — How M0 closes with verification obligations outstanding

Ten requirements are honestly `implemented` at M0 close but cannot meet their frozen acceptance until
a later milestone. The mechanism that lets M0 close without losing them:

**1. Machine-enforced register.** `requirements/implementation_status.json` (not frozen) gains two
fields per entry: `verification_blocked_until` (milestone ID) and `residual` (prose naming exactly
what is missing). `tools/audit_requirements.py` hard-fails if `status == "verified"` while
`verification_blocked_until` is set — converting the anti-inflation rule from a convention into a
gate. This directly overrides
[.claude/skills/close-milestone/SKILL.md:12](.claude/skills/close-milestone/SKILL.md#L12) ("Change
passing requirements from `implemented` to `verified`") for these ten.

**2. Generated register document.** `tools/generate_deferred_register.py` emits
`docs/DEFERRED_VERIFICATION.md` — ID, residual, unblocking milestone, required evidence — regenerated
alongside the traceability matrix and drift-checked in CI.

**3. Milestone-entry gate.** `python3 tools/audit_requirements.py --milestone M1 --check-deferred`
fails if any obligation whose `verification_blocked_until == "M1"` is unresolved at M1 close. The
obligation cannot be forgotten: it becomes a blocking item of the milestone that owes the evidence.

**4. Visibility.** `docs/BUILD_STATE.md` gains a "Deferred verification obligations" line;
`experiments/milestone-reports/M0.md` lists all ten under the mandated "known limitations and blocked
IDs" section, alongside the explicit statement that no later-milestone feature was marked complete.
